# TakeMark

Пакетное сканирование марок «Честный ЗНАК» (лекарства и медизделия, МДЛП) камерой телефона.
Статическое PWA без серверной части: работает в Safari (iOS 16+) и Chrome (Android 10+), в том числе офлайн.

## Что умеет

- Сканирует GS1 DataMatrix подряд; повтор марки — предупреждение, марка не добавляется.
- Читает точечные (каплеструйные) коды на крышках и флаконах: второй декодер libdmtx и режим **«Сфотографировать марку»** — полноразмерное фото с перебором масштабов и фильтров.
- Ручной ввод кода, если марка не читается.
- В выгрузку попадает только `01<GTIN>21<серийный номер>` — криптохвост (91/92/93) отбрасывается.
- Хранит 3 последние сессии (текущая + 2 прошлые) и до 5 последних адресов — только на устройстве.
- Отправка:
  - **«Отправить письмом»** — почтовый клиент с подставленным адресом, коды в тексте письма;
  - **«Поделиться файлом .txt»** — системное меню; адрес копируется в буфер обмена;
  - **«Скачать .txt»**.
- На iPhone в Safari показывает подсказку «Установите на экран „Домой“» (иначе iOS может стереть данные через 7 дней без посещений).

## Публикация на GitHub Pages

Основной способ — без сборки, GitHub просто раздаёт файлы из ветки:

1. Загрузите содержимое папки в репозиторий (вместе со скрытыми `.github` и `.nojekyll`).
2. **Settings → Pages → Build and deployment → Source: «Deploy from a branch»**, ветка `main`, папка `/ (root)` → Save.
3. Через 1–2 минуты сайт доступен по адресу `https://<логин>.github.io/<репозиторий>/`.
   Ход публикации виден на вкладке **Actions** (встроенный «pages build and deployment»).

Библиотека распознавания zxing-wasm при этом загружается с CDN jsDelivr при первом запуске и дальше
хранится в кеше телефона (офлайн работает). Чтобы не зависеть от CDN, один раз положите её в репозиторий:
`sh tools/vendor-zxing.sh`, затем закоммитьте папку `vendor/` (нужны только curl и tar).

### Если публикация зависла

- Отмените зависший запуск на вкладке **Actions** (… → Cancel workflow) и подождите 5–10 минут.
- Проверьте, что в **Settings → Pages** выбран один способ публикации. Если там «GitHub Actions», а не «Deploy from a branch»,
  либо переключите на ветку (рекомендуется), либо запускайте вручную workflow **Deploy to GitHub Pages (Actions)**.
- Если запуск не отменяется больше суток — это сбой на стороне GitHub Pages; помогает принудительная пересборка:
  `gh api -X POST /repos/<логин>/<репозиторий>/pages/builds` или обращение в поддержку GitHub.

Предупреждение `The punycode module is deprecated` в логах Actions выдаёт сам GitHub в своих служебных действиях
(деплой Pages работает на Node.js 24); на сайт оно не влияет. В наших workflow npm больше не используется.

## Проверка

- Тесты разбора кодов: `node tests/gs1.test.mjs` (запускаются на GitHub при каждом push — workflow **Tests**)
- Локальный запуск: `python3 -m http.server 8000` → `http://localhost:8000`.
  Камера на телефоне работает только по HTTPS, поэтому проверять сканирование удобнее сразу на GitHub Pages.

## Обновление приложения

Версия приложения задаётся в трёх местах: `sw.js` (`VERSION = 'takemark-<версия>'`) и `index.html` — текст внизу экрана (`#app-version`),
строка `var V = 'takemark-<версия>'` и `?v=<версия>` у `app.css` и `app.js`. Меняйте все при каждом выпуске — тест проверяет, что они совпадают.
Если на телефоне остался кеш другой версии, страница сама очистит его и один раз перезагрузится. После публикации телефон скачает новую версию
и покажет «Доступна новая версия — Обновить». Файлы приложения берутся из сети (кеш — только без интернета или при медленной сети), поэтому новая версия видна с первого открытия.

## Структура

```
index.html               разметка
css/app.css              стили (светлая и тёмная тема)
js/app.js                интерфейс, сессии, отправка
js/gs1.js                разбор GS1, отсечение криптохвоста, валидация GTIN
js/scanner.js            камера + zxing-wasm + libdmtx
js/dmtx.js               обёртка декодера libdmtx (WebAssembly)
js/dmtx-worker.js        libdmtx в отдельном потоке при живом сканировании
js/imgproc.js            обработка изображения: «склеивание» точек, размытие, масштаб
js/photo.js              распознавание по фото
wasm/dmtx.wasm           libdmtx, собранный в WebAssembly (~44 КБ)
wasm/src/                исходники обвязки и скрипт сборки build.sh
js/storage.js            IndexedDB (запасной вариант — localStorage)
js/export.js             текст файла, имя файла, mailto
sw.js                    офлайн-кеш
manifest.webmanifest     установка на экран «Домой»
icons/                   иконки
tests/gs1.test.mjs       тесты парсера и выгрузки
tools/vendor-zxing.sh    скачать zxing-wasm в vendor/ (curl, без npm)
.github/workflows/       tests.yml — тесты; pages.yml — запасная публикация через Actions (ручной запуск)
docs/brief.md            бриф
```

## Настройки в коде

`js/app.js`: `MAX_SESSIONS` (3), `MAX_EMAILS` (5), `REPEAT_MS` (2500 мс — пауза перед повторным сигналом для марки в кадре),
`PAUSE_BELOW` / `RESUME_ABOVE` (1/3 и 2/3 — распознавание ставится на паузу, когда окно камеры видно меньше чем на 1/3, и возобновляется, когда видно больше 2/3).

`js/scanner.js`: `ZXING_INTERVAL` (120 мс), `DMTX_INTERVAL` (300 мс), `DMTX_AFTER_MISS` (600 мс — libdmtx подключается, если zxing столько времени ничего не находит).
